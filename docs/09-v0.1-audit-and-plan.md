### Reusable as-is
Canonical hashing and closure hashes (`kodehub-core`), renderers (`kodehub-render`), the build
cache logic and test execution (moved into containers), traceability queries (coverage, orphans,
impact, duplicates), the changeset merge transaction, the release diff/bisect, the agent backends
(Claude Code / API / recorded), the MCP tool catalog, and the whole Cytoscape map.

### Conflicts resolved by the spec
Server-wide active project → request-scoped project. Human plan approval and human escalation →
removed (agents escalate to the architect; humans approve only requirement changes, new contexts,
and prod). UI secret → real authentication. Token env-var names → encrypted stored credentials.
`current_version`/`previous_version` → SCD `has_version` edges.

## 2. Architecture decisions for the layering

Recorded as D-043 … in `docs/decisions.md`. Summary:

- **Tenancy:** keep the per-project collection sets (they already guarantee "every node belongs
  to exactly one project"). The project is chosen **per request** (header `x-kodehub-project`),
  through a task-local override in the Arango handle, after a permission check. Cross-project
  records (users, orgs, tokens, settings, credentials, audit, work items, schedules, leases) live
  in global collections and carry a `project` field.
- **Processes:** one Rust workspace, several binaries: `kodehub-server` (API + orchestrator),
  `kodehub-scheduler`, `kodehub-storage`, `kodehub-worker` (build / test / git-import / git-export
  container entrypoint), `kodehub-agent` (agent base image entrypoint) and the existing CLI/MCP.
- **Kubernetes:** Kind cluster `kodehub`, manifests under `deploy/k8s/`, images under
  `deploy/images/`. The orchestrator launches build / test / agent / import containers as
  Kubernetes Jobs through `kubectl` (no extra client library). A `local` runtime that runs the
  same entrypoints as subprocesses is kept for unit tests only.

## 3. Build plan

Each step ends with `make check` green and its acceptance criteria tested in code.

### S1 — Audit and plan (this document) ✅

### S2 — Identity, tenancy, settings, credentials, audit ✅
- Global collections: `users` (human | agent), `orgs`, `memberships` (user→org, role),
  `project_access` (user|org→project, permission), `sessions`, `tokens` (PAT hashes),
  `settings` (scope, key, value), `credentials` (encrypted), `audit`.
- Local accounts (argon2 password hash), session tokens, PATs (hash only, shown once, expiry,
  revocation), agent users linked to a human or org by `acts_for`.
- Auth middleware on every route except `/health`, `/api/auth/login`, `/api/auth/register`;
  request-scoped project with permission check; MCP sends a PAT.
- Layered settings resolver: app → user → project (user-owned) or app → org → project
  (org-owned); per-actor keys from the acting user.
- Credentials: ChaCha20-Poly1305 with a key file outside the graph; subscription tokens only at
  user level on user-owned projects; never logged.
- Audit record for every mutating API call.
- **Accept:** unauthenticated calls get 401; a PAT authenticates and is stored only as a hash;
  revoking it takes effect on the next call; an agent user can never exceed its human's
  permissions; a private project is invisible to another user; settings resolve with the right
  precedence (incl. org fall-through to app default); an org-level subscription token is refused;
  no credential plaintext is present in any collection; an org whose last admin leaves is archived;
  audit rows name actor, on-behalf-of, project and action.

### S3 — Versioned C4 model, requirements, philosophy, use cases, changesets ✅
- `has_version` edges (`validFrom`, `validTo`, `seq`, `state`) for symbols and contexts,
  containers, components; `stable_of` sparse unique key enforces ≤1 stable version.
- Version numbers per node; as-of lookup; artifacts linked by `built_from` edge.
- Requirements gain `kind` (business | technical | …); queries by kind and level; inherited
  master list for a node; per-node counts (own / with children).
- `philosophy` (one per project) replaces missions; `use_cases` (draft | live) with
  `relates_to` and `expected_by` edges; node lifecycle (planned | in_build | ready_for_test | live)
  with roll-up.
- Changesets refit: states `open → submitted → building → reviewing/testing → ready → promoted`
  (+ `rejected`); target releases; `blind_review` setting; all-or-nothing promotion.
- Seed project re-created in the new model.
- **Accept:** a second stable edge is refused by the database; promotion closes/opens edges in one
  transaction; as-of returns the version stable at that time; immutability of versions holds;
  requirement inheritance and counts are correct on seed; review off skips the review gate;
  lifecycle roll-up is correct.

### S4 — Releases and environments ✅
- Selection rules (newest | stable | as_of | explicit) with tag/attribute filters and pins;
  open/cut; `supports` edges; clone to same or lower environment; patch releases; environments
  DEV/TEST/QA/PRE-PROD/PROD with `max_releases`; `in_environment` SCD edges; gates.
- **Accept:** a cut release refuses edits; clone upward is refused; a patch release swaps exactly
  one version and the original is unchanged; PROD never holds two releases; a release is never in
  two environments; tag filters select the right nodes; diff/bisect still work.

### S5 — Kubernetes (Kind), images, storage service ✅
- `deploy/kind.yaml`, `deploy/k8s/*.yaml`, Dockerfiles; `make kind-up`, `make images`,
  `make deploy`; ArangoDB, server, scheduler, storage in the cluster.
- `kodehub-storage`: minimal S3-style object API (PUT/GET/HEAD/LIST), modes local | cloud |
  hybrid, per-project full + incremental backup bundles.
- `make check` integration tests run against the in-cluster ArangoDB and storage.
- **Accept:** `make kind-up deploy` brings up a healthy stack; objects round-trip through the
  storage service; a hybrid backup produces a full then an incremental bundle and a single project
  restores alone.

### S6 — Claim/lease, work queue, scheduler, intents ✅
- `work_items` with priority, lease; atomic claim AQL; caps per agent type from settings;
  `schedules` with cadence defaults (code on landing, component 2h, container 4h, context 12h,
  project 24h, daily always kept); `kodehub-scheduler` binary.
- Intents, Jaccard overlap, sequence / absorb, negotiation records with round limit → architect.
- **Accept:** two claimers never both win; an expired lease is reclaimable; caps are honoured;
  due schedules fire once across two scheduler replicas; overlap ≥ 0.6 absorbs, lower sequences;
  absorbed items count once for retries.

### S7 — Build and test containers, shell tests ✅
- Build Job renders + compiles a changeset closure, uploads the artifact (by `closure_hash`) to
  storage; test Job downloads artifact + shell tests, runs them, reports results.
- Test container types (graph nodes) built from a core image + language / browser layers.
- Formal vs informal runs; baseline blame; promotion on gates.
- **Accept:** a build happens once per closure hash and is tested many times; a Rust test runs
  from the built binary without compiling; a failing test that also failed at baseline does not
  block; a new failure creates a high-priority rework item.

### S8 — Agents ✅
- `kodehub-agent` entrypoint + tiny base image; roles (coding, test author, review, planning,
  architect, import, design, sysadmin) stored in the graph with prompts; ephemeral one-work-item
  lifecycle; per-type caps; credentials injected for the Job only; metering + graceful budget stop;
  escalation after the retry limit; kickoff chain; tests before code.
- **Accept (recorded backend, no key):** the seed demo runs through the queue end to end; the
  reviewer prompt contains none of the coder's messages; a third failure escalates to the
  architect; a project at budget claims no new work while running work finishes; a subscription
  token is never passed to the API backend.

### S9 — Git import and export, backups ✅
- Import Job: clone, parse Rust (`syn`) and Python (`ast` via the test image) into staged units;
  import agent proposes the C4 mapping as a changeset. Export Job: render live versions to files
  and push. Off-site backup of storage and the database.
- **Accept:** importing a fixture repository creates functions (not files) as code nodes; export
  round-trips the seed project to a git repository.

### S10 — UI ✅
- Login, project list + create flow, in-node badges (tests, requirement counts, lifecycle,
  in-progress, candidate, build dot) with overlays replacing the sidebars, requirements cascade,
  use cases, work queue and activity, settings (caps, cadence, engagement, credentials),
  releases and environments. Graph rendering preserved.
- **Accept:** Playwright: sign in, create a project, see badges, open the test overlay, run
  Test now, move a use case to live, promote a release.

### S11 — Remaining ✅
- Speech capture + Whisper transcription container; OAuth for remote MCP (HTTP transport).
